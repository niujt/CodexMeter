# Codex Health · Windows

Tauri 2 + Vue 3 + TypeScript + Rust 应用，当前版本 **0.1.3**。六个页面的顺序、黑白配色、信息分组、统计口径和设置项与 macOS 对齐。

## 功能

| 功能 | Windows 实现 |
| --- | --- |
| 健康报告 | 七天及五小时额度、今日/周用量、近期回复速度、上下文和权限提醒 |
| 使用趋势 | 近七个自然日与近 24 小时 Token 增量趋势 |
| 模型与效率 | 有效轮次、平均端到端耗时、加权回复速度、缓存命中率；Spark 单独显示额度 |
| 项目与用量 | 今日/七天/30 天范围、完整路径、详情、手动关注、复制和打开目录 |
| 预测与风险 | 1/6/24 小时消耗速度加权，样本不足时回退到周期平均速度 |
| 历史记录 | 30 天按小时/模型/项目聚合，筛选、搜索、分页，额度周期及其 Token 总量 |

## 能耗与读取

- 两个窗口共享一个后端刷新任务，前端不轮询读取；新结果通过事件同步。
- 前台至少每 5 分钟，后台至少 15 分钟；Windows 省电模式或低电量时至少 30 分钟。用户选择更长间隔时保留该选择。
- 隐藏窗口停止界面计时；可见窗口仅在额度或速度样本到期时使用一次性计时器。无待处理权限事件时不启动权限维护计时。
- 按文件元数据复用缓存；追加读取只读取增量及首尾校验片段。缓存保留解析检查点、数值和统计元数据，不保存消息正文、命令参数或登录令牌。
- 缓存与目录隔离，重启可复用；无变化刷新不读取源 JSONL、不重复写缓存、不重建聚合。时区变化及统计边界会使聚合失效。
- 图标解码缓存按样式和浅深色复用；同内容的偏好和位置文件跳过写入。

上述验证证明读取量、写入和唤醒减少；没有测得 Windows 实机电池续航提升比例。

## 数据与登录

首次选择 `%USERPROFILE%\.codex` 或实际 Codex 主目录，也可只选 `sessions` / `archived_sessions`。所选目录和设置会持久保存，不主动扫描默认用户目录。

Token 按所选目录统计，不区分账户。选择主目录后，原生后端读取该目录的 `auth.json` 以识别 ChatGPT 登录边界，隔离额度和预测；令牌不进入 WebView、不存入统计缓存。仅选会话目录或使用 API Key 时继续统计 Token，登录额度暂停。账户切换立即清空旧额度，等待当前账户的本地新采样。

会话解析只提取用量、时间、项目、模型及额度。用户主动查询重置历史时，后端使用当前登录向固定 ChatGPT 地址发送只读请求；检查应用更新只访问本仓库公开的更新清单，下载安装只访问发布文件，不使用 ChatGPT 登录凭据，也不上传会话正文。权限 Hook 只记录有限的事件元数据，不接管允许/拒绝决策；安装会备份并合并 `hooks.json`，保留第三方 Hook，需在 Codex `/hooks` 中检查并信任。

## 开发与打包

需要 Node.js 22.12+、Rust stable、Visual Studio Build Tools 的 C++ 桌面开发、Windows SDK 和 WebView2 Runtime。

```powershell
cd windows
npm ci
npm run tauri dev
powershell -ExecutionPolicy Bypass -File .\build-windows.ps1 -Architecture all
```

脚本默认构建 x64 和 ARM64，可单独选择 `x64` 或 `arm64`。NSIS 安装包位于 `src-tauri/target/<目标>/release/bundle/nsis/`；检查应用 EXE 的 PE 架构并输出 SHA-256。当前未配置 Windows 发布签名证书。

```powershell
npm run build
npm test
cargo test --locked --manifest-path usage-core/Cargo.toml
cargo test --locked --lib --manifest-path src-tauri/Cargo.toml
cargo check --locked --manifest-path src-tauri/Cargo.toml
```

浏览器开发服务器仅提供 UI 预览，无法访问本机记录。统计测试使用合成目录；界面验收的 IPC、权限事件和重置历史为测试脚本注入的合成值，生产代码无模拟数据。

## 统计口径

`total_token_usage` 为累计数，连续事件取非负增量；累计回退时开始新计数段，重复事件不累加。缓存输入含于输入，推理输出含于输出。回复速度采用近 15 分钟有效轮次的总输出 / 总耗时；没有可靠增量基线的轮次不计入。日期使用本机时区，七天包含今天与前六天。优先 canonical `codex` 七天额度；最新 canonical 过期后不借用其他额度。读取异常明确提示统计可能不完整。

## Windows 0.1.3 更新

- 额度解析独立于 Token 统计，只有额度变化的记录也会更新，不影响累计 Token 基线。
- 七天、五小时和 Spark 额度显示真实采样时间，明确标注本地采样、非实时。15 分钟后当前数字变为 `—`，另列上次额度；旧数据不再用于当前预测。
- 解析缓存升级后自动重读原文件，恢复旧解析器漏掉的额度记录。
- 在设置 → 关于点击“检查更新”，有新版时可点击“下载并安装更新”。只在用户点击后下载，安装前由 Tauri 验证更新签名，安装时 Windows 应用会退出。
- 更新清单位于 `windows/update/latest.json`，按 `windows-x86_64` 和 `windows-aarch64` 指向各自安装包。新发布完成后更新此清单，不受 macOS 最新 Release 影响。

GitHub Actions 的 `Windows installers` 工作流分别在 Windows x64 和 ARM64 原生 Runner 运行测试、构建 NSIS 安装包，输出程序 EXE、安装包、更新签名、架构及 SHA-256 清单。手动运行 `windows/build-windows.ps1` 时需提供 `TAURI_SIGNING_PRIVATE_KEY`（文件路径或内容）；CI 使用同名仓库 Secret。私钥保存在仓库外，不得提交；发布后先校验两份包，再更新静态更新清单。

首次从 0.1.1 / 0.1.2 升级需要手动安装 0.1.3；安装后具备后续版本的应用内更新入口。更新包签名与 Windows Authenticode 签名不同，当前未配置 Authenticode 证书。
